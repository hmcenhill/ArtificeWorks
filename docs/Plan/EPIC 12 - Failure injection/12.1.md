## The injection registry, and the first lever: fail an inspection

**Labels:** api, backend, reliability, demo

## Summary

Build the backbone the whole epic stands on: an `injected_faults` registry (a table, a service, a
guarded and rate-limited `/system/chaos` write), the world-reset sweep that keeps it from
accumulating, and the first, gentlest consult point — arm an order to **fail its next inspection**,
and watch it route through the ordinary rework/Fault loop. No broker subtlety yet; this story is
about getting the injection *shape* right on the fault that needs no new recovery path.

## Why

The two impressive faults (12.2's transient recovery and poison→DLQ) both need somewhere to read
"is this order armed, and how?" from a *different process* than the one that armed it. That shared
state — its table, its target-by-id contract, its rate limiter, its sweep — is this story. Proving
it on fail-an-inspection is deliberate: a forced inspection failure is resolved by the same code an
ordinary scrap verdict runs (Epic 6's rework loop), so the story can land the entire mechanism
without touching the retry ladder, and 12.2 inherits a registry that already works.

It is also the concrete form of the line architecture.md drew: the dials (10.2) retune the whole
factory; *this* fails one order. Same `/system` prefix, opposite blast radius.

## Tasks

- [ ] **`InjectedFault` entity + `injected_faults` table.** Fields: `Id`, `WorkOrderId` (the target —
      indexed), `Kind` (`FailInspection` for this story; `TransientOnce` / `Poison` reserved for
      12.2), `ArmedUtc`, `ArmedBy`, and a consumed marker (`FiredUtc?` / `ConsumedUtc?` — decide at
      story start between a soft flag and a hard delete on fire; a soft flag lets the dashboard show
      "this order was broken on purpose", which 12.3 may want). Migration `InjectedFaults`.
- [ ] **`ChaosService` (Application).** `Arm(workOrderId, kind, armedBy)` and the query the pipeline
      calls — `TryConsume(workOrderId, kind)` / `IsArmed(...)`. Arming refuses a target that is
      **not a live, in-flight order** (terminal/cancelled orders can't be broken) and refuses a
      `kind`/stage mismatch where it's cheap to detect — the blast radius is bounded at the door, not
      just by convention.
- [ ] **`POST /system/chaos`** (new `ChaosController`, matching `SimulationController` /
      `WorldController` in voice and the `/system` admin-prefix reasoning). Body names the target
      order and the kind; returns what was armed and against which order. ProblemDetails in the house
      style: `chaos_target_not_found` (404), `chaos_target_not_injectable` (409 — order is terminal /
      not in a state this fault can touch). Document, as its neighbours do, that there is **no auth
      yet** and that is deliberate while the demo is people pressing buttons.
- [ ] **Rate limit the endpoint** — the project's first use of ASP.NET's rate limiter, registered in
      the API `Program.cs`. A modest fixed-window or token bucket keyed so one visitor (or a script)
      can't arm faults faster than a human demo needs. This is the "can't grief each other"
      acceptance criterion; size the window at story start and record the choice.
- [ ] **The consult point: fail an inspection.** When an armed `FailInspection` fault matches the
      order under inspection, the verdict resolves to a **fail** for that order's unit(s) and the
      fault is consumed — routing through Epic 6's existing rework/Fault path exactly as a coin-flip
      failure or a manual scrap verdict does. Reuse `RandomVerdictSource` / the inspection service
      rather than adding a parallel verdict path; the fault is one more input to the existing verdict,
      the way `FailureRate` already is. A forced fail records an honest reason (e.g. "Failed by
      injected fault") so the timeline reads truthfully.
- [ ] **World-reset sweep.** Extend `WorldResetService.Sweep` (10.4) to disarm leftover faults — an
      armed-but-never-fired fault must not outlive the order or a reset. It already refuses to touch
      in-flight orders and `dead_letters`; faults are the same class of housekeeping. Keep restock /
      retire behaviour unchanged.
- [ ] **Tests:** arming a live order succeeds and a terminal one is refused; an armed `FailInspection`
      order fails inspection and lands in rework/Fault (not Delivery); the fault fires **once** (a
      second inspection on a re-run order is a fresh coin flip, not a second forced fail); the sweep
      disarms an armed fault; the rate limiter rejects a burst. Unit-testable where possible; the
      inspection routing is the one worth an integration check.
- [ ] Update [docs/architecture.md](../../architecture.md) — the per-order injection registry as the
      counterpart to 10.2's global dials, and its bounded blast radius — and note the new `/system`
      neighbour.

## Acceptance Criteria

- [ ] A visitor can arm one order to fail its next inspection, and that order visibly routes to
      rework/Fault rather than Delivery
- [ ] A fault targets exactly one order and fires exactly once; nothing else on the floor is affected
- [ ] Arming is refused against an order that cannot be broken (terminal/cancelled)
- [ ] The injection endpoint is rate-limited
- [ ] A world reset clears armed-but-unfired faults; in-flight orders and dead letters are untouched
- [ ] The forced failure runs the *same* rework path an ordinary scrap verdict does — no parallel code

## Decisions (to confirm at story start)

- **Registry in the DB, not in memory.** The API arms, the worker fires — different processes, so the
  fault must be shared, durable state. Mirror the `simulation_settings` row and `dead_letters`, not an
  in-process dictionary.
- **`/system/chaos`, targeted by order id.** It belongs with the dials, the dead letters and the world
  reset behind the one deferred admin gate — and it is per-order, the deliberate opposite of the
  global dials.
- **Prove the mechanism on the fault that needs no new recovery.** Fail-an-inspection routes through
  Epic 6's rework loop, so 12.1 can land the entire registry without the retry-ladder subtlety 12.2
  carries. Sequencing on purpose.
- **Soft-consume vs. hard-delete a fired fault** — pick at story start. A soft `FiredUtc` marker lets
  12.3 show "this order was broken on purpose"; a hard delete is simpler. Lean soft if 12.3's copy
  wants the provenance.

## Notes

No auth here — `/system/chaos` sits behind the same deferred gate as its neighbours, flagged in
architecture.md, not built now. Leave the broker faults (`TransientOnce`, `Poison`) as reserved
enum values wired to nothing yet; 12.2 lights them up. If arming needs a field this story didn't
foresee (a stage selector, a count), that is a finding for 12.2 to fold in, not a reason to widen the
table speculatively here.
