## The money shot: chaos in context and the dead-letter inspector

**Labels:** frontend, demo

## Summary

Put the three levers under a visitor's mouse. A contextual **"break something"** affordance on the
order detail — fail this order's inspection, kill a worker mid-task, poison a message — gated to what
the order's current stage allows. And a new **dead-letter inspector** view: list what has parked,
read one, press replay, watch the order finish. Almost entirely frontend; every endpoint it needs
was built in 12.1, 12.2 and 8.3.

## Why

This is the epic's headline criterion — "each injected failure produces a visibly correct recovery on
the dashboard" — and the whole portfolio's closing argument. Until this story the reliability
machinery is real but only assertable in tests; this makes it something a hiring manager *does*, on
their phone, to an order they created. 11.4 already left the architecture diagram able to show a
fault and a parked message; 11.2's feed already streams `work-order.faulted`; 8.3 already exposes the
dead letters. This story is the last mile: the button that arms the fault, and the panel that turns a
`dead_letters` row into a replay a stranger can press.

## Tasks

- [ ] **Contextual chaos panel on the order detail**, alongside 11.3's decision moments in
      `OrderActions` (or a sibling panel). Offer only the fault(s) the order's stage can actually take
      — don't offer "fail inspection" to a Delivery order — the same state-legal gating 11.3 uses, and
      the API's `chaos_target_not_injectable` 409 as the authority when a race loses. Each button calls
      `POST /system/chaos` with the order id and the kind, and surfaces the ProblemDetails as a
      sentence via the shared 11.3 mapper.
- [ ] **Make it read as deliberate sabotage, honestly labelled.** Distinct styling from the ordinary
      decisions (this is `button-danger` territory), and copy that tells the truth: "kill a worker" is
      a *simulated* death, "poison" sends an unprocessable message. The honesty principle is a visible
      feature here, not fine print — the panel explains what will happen and where to watch it recover
      (the feed, the diagram, the DLQ).
- [ ] **The dead-letter inspector — a new view + route.** A list over `GET /system/dead-letters`
      (paged, newest first, the existing filters — `workOrderId`, replayed/unreplayed), each row
      showing event type, order, attempts, parked time and the first line of the error. A detail over
      `GET /system/dead-letters/{id}` with the payload and full error for a human to read. A **Replay**
      button calling `POST /system/dead-letters/{id}/replay`, handling the `202`, the `409`
      `dead_letter_already_replayed` (offer `?force=true` as "replay again"), and the `404`. Add the
      route to `AppLayout` and a nav entry.
- [ ] **Close the loop visibly.** From an order's detail, a parked order links to its dead letter;
      from a dead letter, back to its order. After a replay, the order's live timeline shows it moving
      again (SignalR, or reload — 11.3's pattern). The visitor should be able to follow one order:
      arm poison → see it park → open the DLQ → replay → watch it complete, without hunting.
- [ ] **Feed / diagram legibility (light touch).** The feed already shows `faulted`; make a
      forced-fault or a replay legible in it where cheap (a label in `events.ts`). The diagram already
      colours strain off `/system/stats`' parked count — confirm an injected poison bumps that badge,
      and leave the animation alone. No new backend signal unless a genuine gap appears — if the feed
      *should* show a "parked"/"retried" line and can't, that is a finding about the relay's event
      vocabulary, raised, not silently patched.
- [ ] **Phone-legible** (the standing criterion) — the chaos buttons and the DLQ list must work on the
      screen a recruiter actually clicks the link on.

## Acceptance Criteria

- [ ] A visitor can, from an order they are watching, arm each of the three faults where the order's
      stage allows it, and see the corresponding recovery play out on the dashboard
- [ ] Dead-lettered work is listed, readable, and replayable from the browser; a replay drives the
      order to completion and the UI reflects it
- [ ] A second replay is handled (told it is already replayed, offered force) rather than erroring
      opaquely
- [ ] The chaos affordance is honestly labelled — a simulated worker death is described as one
- [ ] Works acceptably on a phone

## Decisions (to confirm at story start)

- **No dashboard back door — the chaos button calls `/system/chaos`, the replay calls the existing
  DLQ endpoint.** Same principle as 11.3: the UI drives the ordinary (here, admin) surface. The only
  new thing is the lever, and the lever is an endpoint, not a frontend shortcut.
- **Offer only state-legal faults, trust the API as authority.** Client gating is UX; the 404/409
  contract from 12.1 is the guard and drives the message when a race loses.
- **The dead-letter inspector is the second `/system` surface the dashboard renders** (after 11.3's
  dials). Design its list row the way 7.4's timeline and 8.3's DTO were designed — for the view that
  shows it — and reuse the existing `DeadLetterPageDto` shape rather than reshaping the API for the
  UI.
- **Lean on what 11.4 and 11.2 already show.** The diagram's parked badge and the feed's `faulted`
  pulse are existing, honest signals; add a new backend event only if a real legibility gap is found,
  and record it as a finding rather than smuggling in a parallel notification path.

## Notes

Depends on 12.1 (the chaos endpoint) and 12.2 (the broker faults that actually park). Reads best with
the worker and simulation running so an injected fault recovers against a live floor. This is the
epic's demoable finish — after it, a stranger with a mouse can break an order and watch the
reliability machinery heal it, which is the whole reason Epic 8 was built to "design for an
audience." Leaves the deferred admin gate alone: `/system/chaos` and `/system/dead-letters` are
unauthenticated like their neighbours, flagged in architecture.md, fine for the demo.
